# CIA packaging

Turns the built `PapasPizzeria-n3DS.3dsx` into an installable `.cia`.

Run from the project root after `make`:

```sh
./packaging/build_cia.sh
```

Output: `PapasPizzeria-n3DS.cia`.

## What the CIA has

| Feature | Value / behaviour |
|---|---|
| Home-menu icon | `../icon.png` (48×48), baked into the SMDH by `make` |
| Title | "Papa's Pizzeria" / author "zylonity" (SMDH, set in the Makefile) |
| Title ID | `000400000FF4A000` (uniqueID `0xFF4A0`, homebrew range) |
| Boot splash | cxitool's stock logo (this firmware rejects a removed or custom one) |
| Top-screen banner | stereoscopic-3D tilted logo + game tune (`takeorder_music`) |

## Modifications made to the tools

### cxitool — remove the "homebrew" boot logo
`cxitool` hardcodes a `s_homebrewLogo[0x2000]` DARC blob and always injects it as
the ExeFS `logo`. Three spots were changed to omit the logo entirely (clean black
launch; the logo is optional on firmware ≥ 5.0):
- `src/CxiExeFS.cpp` — don't `AddFile("logo", ...)`
- `src/CxiBuilder.cpp` — don't set `logoHash/logoOffset/logoSize`; don't write the blob

Rebuild (no autotools needed):
```sh
cd /home/khaleel/Downloads/3dstools-cxi-stuff
# compile .c as C and .cpp as C++, then link (see build_cia notes)
```
The original binary is backed up as `cxitool.orig-with-logo`.

### bannertool — stereoscopic-3D banner
The stock PNG→CGFX template is a flat quad (all Z = 0), so the Home Menu's stereo
camera shows no depth. `source/utils.cpp` (`convert_to_cgfx`) now tilts the quad
about X — bottom edge toward the viewer (+Z), top edge away (−Z) — and widens the
bounding box so it isn't culled. Depth is tunable at runtime:

```sh
BANNER_TILT=3 ./packaging/build_cia.sh   # 0 = flat, 3 = default, higher = more pop
```

Rebuild bannertool:
```sh
cd /home/khaleel/Downloads/bannertool-3d
cmake -B build -DCMAKE_BUILD_TYPE=RelWithDebInfo && cmake --build build
```

## Notes
- **Title ID — do not use ASCII vanity IDs.** The uniqueID (bits 8-31 of the low
  word) is only 20 bits, `<= 0xFFFFF`. The top nibble of the 24-bit field
  (titleID-low bitmask `0xF0000000`) is the *hardware-restriction* field read by
  the New3DS pm-module: `0` = runs anywhere, `2` = New3DS only. The old
  `0004000050415041` ("PAPA") put `5` there — an undefined value. Old 3DS ignores
  the field, so it launched fine there and as a `.3dsx` (hbmenu launches inside
  another title's process, so the ID is irrelevant), but **New 3DS Home Menu
  refused to launch it** and threw `0xC8804478` (FS / not-found) in the `menu`
  process. Keep the ID in the homebrew range `0xFF000`-`0xFF7FF` with the top
  nibble `0`; `0xFF4A0` was picked to avoid the cxitool default `0xFF3FF` that
  every other cxitool homebrew uses. Saves are unaffected by an ID change — they
  live at `sdmc:/3ds/PapasPizzeria`, not in a title-keyed save archive.
- **3D banner:** the stereo depth can only be verified on hardware (or a home-menu
  environment). Azahar/Citra don't render Home-Menu banners. Tune with `BANNER_TILT`.
